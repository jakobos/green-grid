# C006 · export-image · Export garden to a downloadable PNG image — outcome

Added `src/export/`: `renderExportStage` builds an offscreen Konva stage, `downloadPng` rasterises it at `EXPORT_PIXEL_RATIO = 2.5` and triggers an `<a download>`, and `exportGarden` orchestrates both, names the file `<garden name>.png` (fallback `garden.png`) and destroys the stage. The stage draws the 1 m grid, meter labels on top/left (every 5 m above 40 m), the items sorted by layer, the title with a "W m × H m" subtitle, a north compass, and a legend grouped by layer and deduplicated by `catalogId`. The legend is omitted for empty gardens. The header has an "Export PNG" button. The item drawing in `drawItem` duplicates `GardenItemShape` rather than sharing it, so a style change to items needs both updated. `vite.config.ts` aliases bare `konva` to `konva/lib/index.js`, because otherwise vitest loads Konva's Node entry, which requires the native `canvas` package. The export tests stub `HTMLCanvasElement.getContext`. The repo has no `lint`/`typecheck` npm scripts; `build` runs `tsc --noEmit`. Landed 2026-10-23 as merge f09495e (feature plus a layout fix that separates the subtitle from the top labels and evens out legend spacing), verified by exporting a real PNG from the browser.
